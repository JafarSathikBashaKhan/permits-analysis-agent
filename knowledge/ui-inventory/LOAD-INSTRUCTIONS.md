# UI Inventory — How to Load & Query

The UI inventory is the **source of truth for every selector** in the NPS Backoffice UI.
It's generated by scanning the developer's React source code in
`MNPS-Permission-UI` — not by crawling the live site.

## What's in here

| File / folder | Purpose |
| --- | --- |
| `inventory-INDEX.json` | Module roll-up (counts only) |
| `inventory-<Module>.json` | Per-module element list (27 files, 679 rows total) |
| `UI-INVENTORY.md` | Human-readable summary table |
| `UI-GAPS.md` | Selector collisions to flag to the UI team |
| `pom-builder/` | Generated C# Page Object stubs for the **Builder** module |
| `ui-inventory-scanner.js` | Scans one module |
| `ui-inventory-all.js` | Scans every module + writes summary |
| `pom-generator.js` | Generates Page Object stubs from a `inventory-*.json` |
| `load-to-sqlite.js` | Builds `ui-inventory.sqlite` |
| `demo-queries.js` | Example SQL queries against the loaded DB |

The `.sqlite` file and `node_modules/` are NOT committed — rebuild locally.

## Rebuild

```powershell
cd knowledge\ui-inventory
npm install better-sqlite3
node load-to-sqlite.js
node demo-queries.js
```

Output: `ui-inventory.sqlite` (~1 MB) with two tables — `ui_modules`, `ui_elements`.

## Re-scan when UI changes

```powershell
# Update the source-code path inside ui-inventory-all.js if it's different
node ui-inventory-all.js
node load-to-sqlite.js
```

## Example queries

```sql
-- Every safe (globally unique) data-testid in Permission Builder
SELECT component, value, file, line
FROM ui_elements
WHERE module = 'builder' AND kind = 'data-testid' AND is_unique = 1
ORDER BY component, line;

-- Find which modules collide on an id you're tempted to use
SELECT value, COUNT(*) AS uses, GROUP_CONCAT(DISTINCT module) AS modules
FROM ui_elements
WHERE kind = 'id'
GROUP BY value
HAVING COUNT(*) > 1
ORDER BY uses DESC;

-- High-risk components (no unique selectors at all)
SELECT module, component, COUNT(*) AS elements
FROM ui_elements
GROUP BY module, component
HAVING SUM(is_unique) = 0
ORDER BY elements DESC;

-- Show all selectors on the page that was breaking our tests
SELECT kind, value, line, is_unique
FROM ui_elements
WHERE module = 'builder' AND component = 'BasicInformation'
ORDER BY weight DESC, line;
```

## Schema

```
ui_modules
  module       TEXT PK
  files        INT
  components   INT
  elements     INT

ui_elements
  module       TEXT
  component    TEXT
  file         TEXT
  line         INT
  kind         TEXT   -- data-testid, id, name, aria-label, placeholder, role, button-text, ...
  value        TEXT
  weight       INT    -- selector preference: 100 = data-testid, 80 = id, ..., 20 = role
  is_unique    INT    -- 1 if value is globally unique across the whole UI
  global_count INT    -- how many times this value appears in the codebase
```
