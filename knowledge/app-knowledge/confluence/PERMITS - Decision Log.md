LLPG ingestion

Decision:

As per the discussion held on 16/12/12025, below is the summarization of its outcome,

Call recording - [LLPG ingest Requirement and feasibility analysis-20251216\_170313-Meeting Recording.mp4](https://nsl365-my.sharepoint.com/personal/sudha_s_logicvalley_in/_layouts/15/stream.aspx?id=%2fpersonal%2fsudha%5Fs%5Flogicvalley%5Fin%2fDocuments%2fRecordings%2fLLPG%20ingest%20%20Requirement%20and%20feasibility%20analysis%2D20251216%5F170313%2DMeeting%20Recording%2Emp4&referrer=StreamWebApp%2EWeb&referrerScenario=AddressBarCopied%2Eview%2E4e5129c5%2D2f27%2D4c80%2Db83b%2D079db00def07&ga=1)

Final outcome / decision from the meeting:

No immediate development to ingest full LLPG files is required.

The team agreed to **use the existing bulk address import template (Excel format)** as the **standard input** for councils.

Councils must provide data **in the agreed format**, including **zone (CPZ) mapping** where required.

LLPG files alone are not sufficient\*\*, as they typically do **not include CPZ/zone information**.

If a council only has LLPG data and lacks zone/TRO/GIS mapping:  
The responsibility lies with the council or Paid support can be offered (e.g., via **PCL**) to clean, map, and prepare the data.

**Action item was marked as on hold / not required for now, to be revisited only if a future client explicitly requires LLPG ingestion.**

Conclusion:  
**Standard bulk import file will be used going forward; LLPG ingestion is not pursued unless it becomes a firm future requirement.**
